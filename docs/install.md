# LiveContainer 설치 안내

unsigned arm64 IPA는 소유자의 빌드·패키지 검사 후 배포합니다. 아이폰 실기기 실행은 아직 확인하지 않았습니다. 아래 절차로 설치해 확인합니다.

1. 이 프로젝트의 `Build IPA`가 만든 암호화된 아티팩트를 소유자의 PC에서 `tools/release-ipa.ps1`로 복호화해 `dist/ipa/NFS4-<버전>-b<빌드>.ipa`를 얻습니다.
2. 파일 앱의 iCloud Drive › iOS 포트 IPA에서 최신 NFS4 IPA를 확인하고 LiveContainer의 + 버튼에서 선택합니다. 이전 버전은 PC의 버전별 보관함에 남깁니다. 앱의 기본(비공유) 컨테이너를 사용합니다.
3. 앱을 한 번 실행해 `LiveContainer › Games › NFS4 › game` 폴더를 만듭니다.
4. PC에서는 공용 `E:/ios-ports/PC에서-받기-서버.cmd`의 서버만 사용합니다. 공용 서버의 시작·중지·재시작은 사용자가 합니다. 프로젝트의 기존 .cmd 실행기는 폐기 안내만 표시합니다. Python 복사본은 PC 안 시험 전용(`--port 18765 --host 127.0.0.1`)이며 휴대폰 전송용으로 사용하지 않습니다. NFS4 등록이 필요하면 `docs/공용폴더-반영요청.md`를 사용자에게 반영 요청합니다.
5. 같은 와이파이에서 앱의 `PC에서 받기`를 선택합니다. 목록의 모든 파일을 받은 뒤 실행합니다.
6. 문제가 생기면 앱 설정에 표시되는 버전·빌드 번호와 `LiveContainer › Games › NFS4 › save`의 `nfs4host.log`, `nfs4host.prev.log`를 확인합니다.

앱 ID: `io.github.avoseed.nfs4`. 앱 데이터 폴더: `NFS4`. 원본 게임 데이터는 IPA와 저장소에 포함하지 않습니다. 재컴파일 입력 exe/DLL 3개는 공개 저장소에서 암호화된 묶음으로만 보관하며, 키는 소유자의 PC와 저장소 Secret에만 둡니다.

LiveContainer 공식 설치·IPA 선택 안내: https://github.com/LiveContainer/LiveContainer#installing-apps
실기기에서 메뉴·레이스·사운드·조작·발열은 사용자가 직접 확인해야 하며, PC 검증만으로 아이폰 실행 성공을 확정하지 않습니다.

차량 텍스처 개선은 앱이 로딩할 때 적용하므로 기존 게임 데이터를 다시 받을 필요가 없습니다. RGB 경계의 계단 현상을 줄이고 원본 도색·유리 마스크를 유지합니다. 원본에 없는 새로운 디테일을 생성하는 기능은 아닙니다.

발열 대응: 기기가 따뜻해지거나 저전력 모드이면 게임과 표시를 함께 30fps로 낮춥니다. 매우 높은 온도 상태에서는 15fps로 제한하고, 정상 온도를 20초 유지한 후 선택한 프레임 설정으로 복귀합니다. 실제 발열·배터리 사용량은 기기에서 확인해야 합니다.

메뉴·일시정지 화면은 자동 30fps이며, 주행할 때 선택한 프레임 설정으로 돌아갑니다. 긴 세션의 오류를 확인할 때는 save의 nfs4host.log·nfs4host.segment.log·nfs4host.prev.log를 함께 보관합니다.

## 공통 편의 기능 (0.3.0, 2026-11-15) — 기기 미확인

`E:\ios-ports\README.md` 4·9·10절의 공통 기능을 넣었습니다. **iOS 컴파일(CI)과 아이폰·아이패드 실행은 아직 확인하지 않았습니다.** PC에서는 iOS 코드를 컴파일할 수 없어 코드 검토만 했습니다.

- 세이브 공유: 설정 › 세이브 공유에서 파일 앱 폴더(iCloud Drive 등)를 고르거나 'PC와 공유'를 켭니다(`ios/port_save_sync.m`, wog3-ios 3022e5f 판 복사). 대상은 데이터 루트의 `save/` 전체(게임이 쓰는 파일이 게임 폴더와 같은 구조로 쌓이는 곳)이고 `.log`·`.txt`·`.part`는 올리지 않습니다. PC 쪽 위치는 `E:\ios-ports\saves\NFS4\save\<게임 폴더 기준 경로>`입니다. 게임 시작 전에 맞추고(PC는 마지막 주소 한 곳에만 1.5초), 앱을 벗어날 때는 올리기만 합니다. 게임 중 '지금 맞추기'로 받은 세이브는 앱을 다시 열면 확실히 반영됩니다.
- 게임 멈춤: 설정·모든 창, PC에서 받기 화면, 버튼 편집, 세이브 맞추기 중, 앱 비활성 동안 게임 시계(`plat_ticks_us`)를 멈추고 게임 스레드는 `plat_sleep_*`에서 기다리며 소리는 무음입니다. 다시 켜면 멈춘 시각에서 이어 갑니다.
- 게임 주 스레드 우선순위: `QOS_CLASS_USER_INTERACTIVE`. 효과·발열은 기기에서 재야 합니다.
- 소리: Ambient → Playback(무음 스위치를 켜도 게임 소리가 남). '다른 앱 소리와 함께'(기본 켬)는 MixWithOthers이며 바꾸면 바로 적용합니다. 다른 앱이 재생 중일 때 음악만 쉬는 기능은 넣지 않았습니다(게임 음악과 효과음이 모두 같은 DirectSound 보조 버퍼라 구별할 수 없음).
- PC에서 받기: 시작 검사는 표시 파일(`.pcimport-incomplete`)만 보고, `.part`를 찾는 폴더 훑기는 처음 한 번만 합니다(`partScanDone`). 게임이 있으면 시작 전에 PC에 새 파일이 있는지 짧게(약 1.5초) 묻고 '받기 / 건너뛰고 게임 시작'을 고릅니다. 멈춘 업데이트 화면에도 '건너뛰고 게임 시작'이 있습니다.
- PC로 진단 보내기: 앱 로그(`nfs4host.log`, `.prev.log`, `.segment.log`)와 마지막 크래시 기록을 `POST /api/diag/NFS4/<이름>`으로 보냅니다. 앞 실행이 `CRASH:`/`FATAL:`로 끝났으면 그 로그를 `save/nfs4crash-last.log`로 남기고 PC가 보일 때 자동으로 보냅니다.
- 설정 순서: 제목 `NFS4 v<버전> (빌드 <번호>)` → 세이브 공유 → 다른 앱 소리와 함께 → 화면(화면비·안티에일리어싱·프레임) → 패드(배치·투명도·키보드 입력) → PC에서 받기 → PC로 진단 보내기 → 도움말 → 닫기.
- 아이패드 버튼 위치는 바꾸지 않았습니다. 와이드 레이스는 화면 비율(최대 16:9)로 그려 아이패드에서는 위아래 띠가 생기지 않고, 4:3일 때 11인치 아이패드의 양옆 여백(약 43pt)은 가장 작은 버튼(52pt)보다 좁습니다.

기기에서 확인할 것: 설정을 열고 닫을 때 레이스 시계·소리가 멈췄다 이어지는지, 홈으로 나갔다 돌아올 때 같은지, 키보드 입력으로 이름이 들어가는지, 세이브가 다른 기기·PC로 오가는지, 진단이 `E:\ios-ports\logs\diag\NFS4`에 오는지, 무음 스위치를 켠 채 게임 소리와 다른 앱 음악이 함께 나는지.

추가(같은 0.3.0, 기기 미확인):
- 하드웨어 키보드: 누른 키를 자리 그대로(HID → DirectInput 스캔 코드) 게임에 넘깁니다. 게임의 기본 키 표가 그대로 적용됩니다(방향키, Space, A/Z, C, B, H, L, R, S, Esc, Tab, Enter). 창이 열려 있으면 키는 그 창이 받습니다.
- 소리 복구: 전화·Siri·알람으로 끊긴 뒤 세션을 다시 켜고 출력 장치를 다시 시작합니다(끊김이 백그라운드에서 끝났으면 앱이 앞으로 올 때). 로그에 `audio: interruption`, `audio: output restarted`가 남습니다.
- 발열 기록: 실제로 달린 시간 기준으로 처음 15분은 1분마다, 그 뒤는 5분마다 `thermal: N min of play, state …, cap … fps`를 남깁니다. 프레임 시간은 기존 `glide: … frames, … fps, frame … ms` 줄에 있습니다. QoS 변경의 효과는 0.2.0 로그와 같은 장면에서 견주어 봐야 합니다.

## 기기 없이 한 점검 (0.3.1, 2026-11-15) — 기기 미확인

FF7 포트가 11-15에 한 것처럼 코드를 읽어 아이폰·아이패드에서 생길 문제를 미리 찾았습니다. **CI 컴파일과 기기 실행은 아직 확인하지 않았습니다.**

- PC에서 받기가 끝나면 자동 잠금을 다시 켜던 것을 없앴습니다. 받은 뒤 곧바로 시작한 게임을 패드로만 하면 화면이 꺼졌습니다(앱은 실행할 때부터 자동 잠금을 끕니다).
- 파일 앱에서 게임 폴더 가져오기: `game/.NFS4-copying`에 먼저 복사하고 다 된 뒤에 `game/NFS4`로 옮깁니다. 예전에는 기존 폴더를 먼저 지워서, 복사가 중간에 끊기면 반쪽 게임이 시작되고, 앱 자신의 `game/NFS4`를 고르면 원본을 지운 뒤 복사하려 했습니다. 점(.)으로 시작하는 폴더는 게임 폴더 찾기에서 건너뜁니다.
- 4:3 아이패드(옆 띠가 없는 화면)에서 메뉴 버튼(▲▼◀▶, 확인·뒤로, ⚙︎·키보드)이 화면 밖으로 반쯤 나가던 것을 화면 안으로 당겼습니다. 이때는 메뉴 그림의 가장자리에 조금 겹칩니다.
- 렌더 크기: 화면 높이만 보고 키우던 것을 화면 폭도 보게 했습니다(FF7 29db7e2와 같음). 아이패드의 16:9 레이스가 그려진 뒤 다시 줄여 보이던 만큼의 GPU 일을 덜 합니다. 폭이 충분한 아이폰은 그대로입니다.
- `game`·`mods` 폴더를 iCloud·컴퓨터 백업에서 뺐습니다(PC에서 다시 받을 수 있는 수백 MB). `save`는 백업에 남습니다.
- 게임 앱 분류와 `GCSupportsGameMode`를 넣어 iOS 18 게임 모드가 켜지게 했습니다.
- 메모리 경고가 오면 `MEMORY warning: N MB still available` 줄을 로그에 남깁니다.
- 게임 폴더 안내의 단독 설치 경로를 아이패드에서는 '나의 iPad'로 보여 줍니다.

기기에서 확인할 것:
- 아이폰 가로 왼쪽/오른쪽을 바꿀 때 버튼·⚙︎·그림이 다이내믹 아일랜드를 피하는지, 홈 표시줄 근처에서 페달을 밟아도 레이스가 끊기지 않는지.
- 아이폰 SE처럼 낮은 화면에서 PC에서 받기 화면(안내 글·주소 칸·오류 글)이 위아래로 잘리지 않는지, 주소 칸을 누르면 키보드가 칸을 가리지 않는지.
- 설정 창(항목 11개)이 가로 아이폰에서 스크롤되어 '닫기'까지 닿는지.
- 4:3 아이패드에서 메뉴 버튼이 메뉴 글자를 가리지 않는지, 11인치 아이패드 레이스에서 버튼 배치가 손에 맞는지.
- 처음 실행할 때 '로컬 네트워크' 허용 창이 뜨는 동안 게임이 멈춰 있는지(시작 전 업데이트 확인이 처음으로 PC를 찾습니다).
- 트랙을 읽는 중(긴 로딩)에 홈으로 나갔다 돌아와도 튕기지 않는지. 로딩 중에는 프레임마다 쉬는 곳(`pace_swap`)을 지나지 않아 게임이 곧바로 멈추지 않을 수 있습니다.
- 긴 레이스 뒤 로그에 `MEMORY warning`이 있는지, 있으면 남은 MB.
- 설정 앱 › iCloud › 저장 공간 관리 › 백업에서 NFS IV가 수백 MB에서 세이브 크기로 줄었는지(단독 설치).
